# Работа с firmware через GitHub

Канонический репозиторий: twosems/ha-boiler-bridge. Карточки: twosems/boiler-control-card. С20.10.2026 новые изменения ведём от актуального принятого GitHub SHA, в отдельной fix/feature ветке и через PR. Ветка синхронизации текущего переноса: feature/firmware-history-through-16-20261020; до её слияния продолжать от неё, не от старогоmain. Не создавать новую несвязанную локальную историю.

1. git fetch; status/branch/HEAD; прочитать правила и CURRENT; сверить реальные исходники, target и известные ограничения.
2. Новый изменённый firmware — новый номер и отдельный каталог, например следующая .17. Не перезаписывать .16 и старые snapshots. Для карточки менять её собственный репозиторий, а не прошивку ради frontend.
3. Минимальное изменение, релевантные проверки, полный build log/manifest и SHA256 OTA/factory. Build PASS, deployment и физическое подтверждение отражать отдельно.
4. До окончания этапа исходники/тесты/описание/реестр/контекст/открытые задачи закоммитить и отправить в GitHub. Приватные образы хранить зашифрованными для существующего recovery public key; private key никогда не читать для обычной разработки и не коммитить.
5. Открыть PR с конкретным поведением, проверками и ограничениями. OTA/restart/изменение котельных настроек выполняются отдельно в пределах явной команды пользователя; сохранение в GitHub не является развёртыванием.
6. После установки записать точный hash, версию, время и результаты наблюдения; передать ссылку на GitHub SHA/PR следующему чату.

В .16 доступны template switch ACTIVE_REQUESTS (optimistic=false/ALWAYS_OFF), COMMAND_STATUS и BRIDGE_DIAG JSON в атрибутах. ON требует проверки транспорта/меток; UI не рисует разрешение оптимистично. Все safety gates сохранять. Историю и старые теги не переписывать, shared branches не force-push.

Тесты актуальной.16: `python tools/test_boiler_v16.py`; `node tools/test_web_v16.mjs` (из корня). g++ с ASan/UBSan нужен для первого. Тесты исходников не отправляют команды устройству. Для сборки ESPHome2026.9.0/IDF5.5.5 сprivate secrets.yaml; сборочный каталог каждой новой версии отдельный. Старый случай общего buildcache.15/.16 сохранён вреестре, не повторять.
