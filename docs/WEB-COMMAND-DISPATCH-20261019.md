## Подтверждение дефекта
Пользователь: 19.10, физический экран остаётся главным после нажатий «Режимы работы».
Свежая диагностика .13: GUARDED_CONTROL, write_capabletrue, marker_verifiedtrue,
ownership_faultfalse, click_id0/stage0; command_status только CONTROL_ARMED.
В www/boiler.js render выставляет disabled/aria-disabled для data-btn, но отсутствует
обработчик click для этих кнопок. Обработчики data-local (настройки/допуск) есть.
Поэтому допуск включается, но функция press для кнопок котла не вызывается.
Это отдельный подтверждённый дефект GUI; прежнее изменение задержки транспорта
в .13 не могло исправить отсутствие самого веб-запроса.

## Исправление .14
Один делегированный click-handler на постоянном корневом DOM-узле.
Нажатие вызывает существующую press(name, element); проверка допуска, свежести,
ошибок, marker proof и подтверждение опасных действий остаются прежними.
Повторный render не добавляет обработчики. Рендер откладывается на время жеста
pointer/keyboard, чтобы SSE не удалил цель между началом нажатия и native click.
Свежие индикаторы допуска при этом обновляются, а press повторно проверяет допуск.

UART/transaction-core/ownership/timing/GPIO/watchdog/очереди/TTL не менялись.
В C++ транспорта изменена только строка номера версии; YAML также только версия.
MQTT entity IDs и сохранённые настройки не менялись.
Авторизация админки и проблема ownership_fault/восстановления опроса не исправляются
этим выпуском: это отдельные задачи, причина ownership-сбоя пока не доказана.

## Проверка
tools/test_web_click_dispatch.mjs исполняет фактический JS .13 и .14 в Node VM:
.13 — доступная кнопка, ноль запросов; .14 — один корректный POST на MODEBTN,
нет дублирования после render; цель жеста сохраняется при SSE; keyboard PASS;
OFF/ошибка допуска блокируют запрос. Все fetch в тесте подменены, реального
обмена с котлом нет. Node syntax check PASS.
Это проверка JS с моделируемым DOM, не полноценный реальный браузер/экранный тест.
Действие Nextion и штатного контроллера при реальной команде ещё не подтверждено.
Унаследованные риски пары PRESS/RELEASE и смены страницы требуют проверки на HMI.
Никакие режимы/подача/вентилятор автоматически не тестировались.
