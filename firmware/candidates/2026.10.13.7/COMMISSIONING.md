# Прошивка 2026.10.12.6: установка по USB

Полный кандидат собран; на физическом котле не испытан. ACTIVE_REQUESTS изначально выключен. Секреты и бинарники находятся в частном пакете.

1. На месте убедиться, что котёл и экран готовы к прерыванию связи при сбросе ESP. Подключить ту же ESP32-WROOM-32 по USB, определить COM-порт. Не менять проводку UART и не подавать конфликтующее питание.
2. Установить Python 3 и зависимость: `python -m pip install esptool==4.12.0`.
3. Из распакованного каталога выполнить (заменить COM5 фактическим портом):

```text
python office_flash.py --port COM5 --ack-bridge-interruption --flash-factory boiler-2026.10.12.6.factory.bin
```

Помощник сначала проверяет хэш и чип, сохраняет полный дамп flash и JSON в flash-backups, затем пишет factory и проверяет записанные байты. Ошибка чтения/хэша останавливает запись. Сохранить дамп: это точная копия неизвестного текущего состояния, а не доказанно рабочая прошивка.

4. Проверить штатный экран/котёл, двустороннюю связь и счётчики моста. Подключение ожидается к 2Soffice; адрес искать сканером/DHCP, прежний 192.168.1.172 не гарантирован. Учётные данные Web/AP см. ACCESS.txt. Проверить MQTT 192.168.1.203 и появление сущностей в HA.
5. При необходимости BOOT удерживать 5 секунд после загрузки: Boiler-Setup, адрес http://192.168.4.1, окно 5 минут. Это не действие во время подачи питания и не ROM bootloader.
6. ACTIVE_REQUESTS включать только после проверки bkcmd=0, очередности ответов, смены страниц/касания экрана, поздних ответов и работы press/release. Не проверять автоматически вентилятор, подачу, реверс или запуск горелки. Успешная запись не доказывает работу этих функций.

Восстановление точного дампа (также сбрасывает ESP и сначала сохраняет текущее состояние):

```text
python office_flash.py --port COM5 --ack-bridge-interruption --restore flash-backups/ИМЯ-ДАМПА.bin
```

Бинарник OTA приложен для будущего обслуживания; сейчас использовать USB и factory. Без резервного ESP невозможно обещать безрисковую замену единственного работающего моста.
